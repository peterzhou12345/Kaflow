# Kaflow 用户操作手册

> **Kaflow：世界上最轻量、最小的 Kafka 客户端之一。** 约 8 MB 的单文件程序，下载、解压、启动即可使用。

Kaflow 是一个面向终端用户的本地 Kafka 图形客户端。它只连接你填写的 Kafka 集群，不自带 Kafka 服务端，也不会把消息或凭据上传到第三方。它采用单文件执行方式，追求极小体积和快速启动。

## 1. 启动程序

根据电脑系统选择启动文件：

| 系统 | 启动方式 |
| --- | --- |
| macOS Apple Silicon（M1/M2/M3/M4） | 双击 `启动 Kaflow.command` |
| macOS Intel | 双击 `启动 Kaflow.command` |
| Windows 64 位 | 双击 `启动 Kaflow.bat` |
| Ubuntu/Linux x86_64 | 执行 `sh 启动 Kaflow.sh` |
| Ubuntu/Linux ARM64 | 执行 `sh 启动 Kaflow.sh` |

程序启动后会打开本机浏览器。若没有自动打开，复制终端里以 `http://127.0.0.1:17893/#token=` 开头的完整地址到浏览器。地址中的 `#token` 不能删掉。

程序运行期间保持终端窗口打开，按 `Ctrl+C` 退出。默认只监听本机地址，不要把它暴露到公网。

## 2. 添加 Kafka 连接

点击左侧连接卡片或「添加连接」，填写：

- **连接名称**：自定义，例如 `开发环境`。
- **Bootstrap servers**：填写 Kafka 的实际地址和端口，多个地址用逗号分隔，例如 `broker-1.example.com:9092,broker-2.example.com:9092`。
- **认证方式**：按服务端选择「无认证」「SASL / PLAIN」「SCRAM-SHA-256」或「SCRAM-SHA-512」。
- **用户名/密码**：仅 SASL 认证时填写。
- **启用 TLS**：服务端使用 `SSL` 或 `SASL_SSL` 时勾选。
- **CA 证书**：服务端使用私有 CA 时，粘贴完整 PEM 证书（包括 `BEGIN CERTIFICATE` 和 `END CERTIFICATE`）。从 YAML 复制时保留内容即可，程序会自动清理缩进。
- **客户端证书/私钥**：只有服务端要求双向 TLS（mTLS）时填写，必须是配对的 PEM 内容。

勾选「记住名称、地址和认证方式」只保存非敏感配置，不保存密码、证书或私钥。连接成功后，凭据只存在当前程序内存中。

### 示例：SASL_SSL + PLAIN

```text
Bootstrap servers: studio3-221.com:30093
认证方式: SASL / PLAIN
用户名: admin
密码: 服务端实际密码
启用 TLS: 是
CA 证书: 粘贴服务端 CA PEM
```

如果原 Java 配置使用 `ssl.endpoint.identification.algorithm: ""`，说明服务端证书的域名可能与连接地址不同。Kaflow 已兼容此类私有集群配置；仍应优先让证书 SAN 包含实际 Broker 域名。

## 3. Topics

连接成功后，Topics 页面会显示 Topic 名称、分区数、副本数和状态。

- 顶部搜索框按名称筛选。
- 「显示内部 Topic」用于显示下划线开头的内部 Topic。
- 「创建 Topic」填写名称、分区数和副本数后提交，操作会直接发送到 Kafka。
- 删除 Topic 前必须输入完整 Topic 名称确认，删除不可撤销。
- 点击 Topic 可打开详情。

## 4. 查看消息

在 Topic 详情的「消息」页选择：

- **最近消息**：从每个分区尾部向前读取。
- **最早可用消息**：从 retention 保留的最早 Offset 读取。
- **指定 Offset**：从填写的 Offset 开始读取。
- **分区**：可选择全部分区或单个分区。
- **最多条数**：限制本次最多返回 50、100、500 或 1000 条。

读取是手动快照，不加入消费组，也不会提交消费位点。跨分区结果不保证全局顺序；页面会显示分区、Offset、时间、Key、Value 和 Headers。点击一行可查看完整内容，并可导出 JSON。

## 5. 发送消息

点击 Topic 详情中的「发送消息」：

- 分区留空表示由 Kafka 自动分配，也可以指定分区号。
- Key 可留空。
- Value 支持普通文本或 JSON。
- Headers 使用 JSON 数组，例如 `[{"key":"source","value":"kaflow"}]`。
- 勾选 Tombstone 会发送 `null` Value，常用于 compacted Topic 的删除标记。

收到 Kafka Broker 确认后页面才显示发送成功。单条 Key、Value、Headers 内容合计限制为 1 MiB。

## 6. 消费组和 Brokers

- **消费组**：查看组状态、成员数、提交 Offset、末尾 Offset 和 Lag。查询不会修改消费组。
- **Brokers**：查看 Broker ID、地址、端口、Rack 和 Controller。
- **分区 & Offset**：查看 Topic 每个分区的 Leader、Replicas、ISR、起始 Offset 和结束 Offset。

## 7. 常见错误

### `certificate is valid for ..., not your-domain`

证书链可信，但证书 SAN 不包含你填写的 Broker 域名。确认地址使用证书中的域名，或确认服务端是否要求关闭主机名校验。

### `certificate signed by unknown authority`

CA 证书未填写、内容不完整，或不是签发 Broker 证书的 CA。重新粘贴完整 PEM 区块。

### `connection reset by peer`

常见原因是端口协议不匹配，例如把 PLAINTEXT 端口当成 SASL_SSL，或把内部监听端口当成外部监听端口。确认 `bootstrap.servers` 和监听协议。

### `SASL authentication failed`

确认用户名、明文密码和 SASL 机制。配置中的 `ENC(...)` 通常是应用内部加密值，不能直接当作密码填写。

### `advertised.listeners` 相关错误

Bootstrap 地址能访问不代表 Broker 返回的地址能访问。Kafka 会在连接后返回 `advertised.listeners`，这些地址也必须能从当前电脑访问。

## 8. 安全提示

密码、证书和私钥不会写入保存的连接配置。不要把启动 URL、密码或客户端私钥发给他人。你曾经在聊天中暴露过的密码建议在服务端更换。

## 9. 版本和文件

构建产物位于 `dist/`：

- `kaflow-darwin-arm64`：macOS Apple Silicon
- `kaflow-darwin-amd64`：macOS Intel
- `kaflow-windows-amd64.exe`：Windows 64 位
- `kaflow-linux-amd64`：Ubuntu/Linux x86_64
- `kaflow-linux-arm64`：Ubuntu/Linux ARM64

从源码重新构建所有平台：

```sh
sh scripts/build-all.sh
```

# Kaflow User Guide (English)

> **Kaflow: one of the world's lightest and smallest Kafka clients.** An approximately 8 MB single-file application that starts without a runtime installation.

Kaflow is an end-user oriented local Kafka GUI client. It connects directly to the Kafka cluster you enter. It does not include a Kafka server and does not upload messages or credentials to a third party. It is distributed as a small standalone executable for fast startup and simple deployment.

## 1. Start Kaflow

Choose the launcher for your operating system:

| System | Launcher |
| --- | --- |
| macOS Apple Silicon (M1/M2/M3/M4) | Double-click `启动 Kaflow.command` |
| macOS Intel | Double-click `启动 Kaflow.command` |
| Windows 64-bit | Double-click `启动 Kaflow.bat` |
| Ubuntu/Linux x86_64 | Run `sh 启动 Kaflow.sh` |
| Ubuntu/Linux ARM64 | Run `sh 启动 Kaflow.sh` |

The program opens a browser. If it does not, copy the complete URL printed in the terminal. It starts with `http://127.0.0.1:17893/#token=`. Keep the `#token` fragment intact.

Keep the terminal window open while using Kaflow. Press `Ctrl+C` to quit. The server listens on the local machine only by default; do not expose it to the public internet.

## 2. Add a Kafka connection

Click the connection card or **Add connection**:

- **Connection name**: Any name, such as `Development`.
- **Bootstrap servers**: Kafka addresses and ports, separated by commas, for example `broker-1.example.com:9092,broker-2.example.com:9092`.
- **Authentication**: Choose `None`, `SASL / PLAIN`, `SCRAM-SHA-256`, or `SCRAM-SHA-512`.
- **Username / Password**: Required for SASL authentication.
- **Enable TLS**: Check this for `SSL` or `SASL_SSL`.
- **CA certificate**: For a private CA, paste the complete PEM certificate including both boundary lines. Indented YAML copies are normalized automatically.
- **Client certificate / private key**: Fill these only when mutual TLS (mTLS) is required.

The save option stores only the connection name, addresses, TLS choice, and SASL choice. It never stores passwords, certificates, or private keys.

### Example: SASL_SSL + PLAIN

```text
Bootstrap servers: studio3-221.com:30093
Authentication: SASL / PLAIN
Username: admin
Password: the actual server password
TLS: enabled
CA certificate: the server CA PEM
```

If the original Java client uses `ssl.endpoint.identification.algorithm: ""`, the cluster may use private certificate names. Kaflow supports this configuration, although adding the real Broker hostname to the certificate SAN remains preferable.

## 3. Topics

The Topics page shows topic names, partition counts, replica counts, and status.

- Search filters topics by name.
- **Show internal topics** displays internal topics such as those beginning with an underscore.
- **Create Topic** sends a real create request to Kafka.
- Deleting a topic requires typing its complete name and cannot be undone.
- Click a topic to open its inspector.

## 4. Read messages

In the topic inspector, choose:

- **Latest messages**: Read backward from the end of each partition.
- **Earliest available**: Start at the oldest offset retained by Kafka.
- **Specific offset**: Start at the offset you enter.
- **Partition**: Read all partitions or one partition.
- **Maximum records**: Return at most 50, 100, 500, or 1000 records.

Reads are manual snapshots. Kaflow does not join a consumer group and does not commit offsets. Results across partitions are not globally ordered. Each record shows partition, offset, timestamp, key, value, and headers. Click a row for the full record and Base64 bytes; results can be exported as JSON.

## 5. Produce messages

Click **Send message** in the topic inspector:

- Leave partition empty for Kafka's automatic partitioner, or choose a partition.
- Key is optional.
- Value accepts text or JSON.
- Headers use a JSON array, for example `[{"key":"source","value":"kaflow"}]`.
- **Tombstone** sends a `null` value, commonly used with compacted topics.

Kaflow reports success only after the Broker acknowledges the record. The combined key, value, and header content is limited to 1 MiB.

## 6. Consumer groups and Brokers

- **Consumer groups**: View group state, member count, committed offsets, end offsets, and partition lag. This query does not modify groups.
- **Brokers**: View Broker IDs, addresses, ports, racks, and the Controller.
- **Partitions & Offset**: View each partition's leader, replicas, ISR, start offset, and end offset.

## 7. Common errors

### `certificate is valid for ..., not your-domain`

The certificate chain is trusted, but its SAN does not contain the hostname you entered. Use a hostname present in the certificate or confirm that the server intentionally disables hostname verification.

### `certificate signed by unknown authority`

The CA is missing, incomplete, or not the CA that signed the Broker certificate. Paste the complete PEM blocks again.

### `connection reset by peer`

The port protocol may be wrong, for example using a PLAINTEXT port as SASL_SSL, or using an internal listener from outside the cluster. Confirm `bootstrap.servers` and listener protocols.

### `SASL authentication failed`

Check the username, clear-text password, and SASL mechanism. An `ENC(...)` value is usually an application-encrypted value and cannot be entered as the password directly.

### `advertised.listeners` errors

The bootstrap address can be reachable while the addresses returned by Kafka are not. Every advertised Broker address must be reachable from this computer.

## 8. Security

Passwords, certificates, and private keys stay in the current process memory. Do not share the startup URL, password, or client private key. Rotate any password that has been exposed in a chat or log.

## 9. Builds

Platform binaries are in `dist/`:

- `kaflow-darwin-arm64`: macOS Apple Silicon
- `kaflow-darwin-amd64`: macOS Intel
- `kaflow-windows-amd64.exe`: Windows 64-bit
- `kaflow-linux-amd64`: Ubuntu/Linux x86_64
- `kaflow-linux-arm64`: Ubuntu/Linux ARM64

Build all platforms from source:

```sh
sh scripts/build-all.sh
```
